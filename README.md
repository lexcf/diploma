# Детектор аномалий сетевого трафика

Система обнаружения аномалий в сетевом трафике на основе обучения без учителя (Isolation Forest). Поддерживает три режима работы: ручное обучение, ручная детекция и автономный режим службы/демона с сохранением состояния между перезагрузками.

## Как это работает

### Общая схема

```
┌──────────────────────────────────────────────────────────────────┐
│                      РЕЖИМ ОБУЧЕНИЯ (train)                      │
├──────────────────────────────────────────────────────────────────┤
│  Интерфейс → Захват пакетов → Извлечение признаков →             │
│  → Агрегация по окнам → Isolation Forest → anomaly_model.pkl     │
└──────────────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────────────┐
│                     РЕЖИМ ДЕТЕКЦИИ (detect)                      │
├──────────────────────────────────────────────────────────────────┤
│  Интерфейс → Захват пакетов → Признаки                           │
│       ↓                           ↓                              │
│  TrafficLogger          TimeWindowAggregator → Модель            │
│  (буфер N мин)              (окна 5 с)             ↓             │
│       ↓                                       Аномалия?          │
│       └───────────────────────────────────────── Да →            │
│           лог (файл + терминал) + SQLite + ZIP → веб-сервер      │
└──────────────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────────────┐
│                    РЕЖИМ СЛУЖБЫ (daemon.py)                      │
├──────────────────────────────────────────────────────────────────┤
│  Запуск → есть state_file? → продолжить обучение                 │
│         → есть model.pkl?  → сразу перейти к детекции            │
│         → иначе            → начать обучение с нуля              │
│  После обучения: state_file удаляется, запускается детекция       │
└──────────────────────────────────────────────────────────────────┘
```

### Режим обучения

1. Захват пакетов с заданного интерфейса в течение N минут.
2. Из каждого пакета извлекаются признаки (IP, порты, протокол, длина, TTL и т.д.).
3. Пакеты группируются в **временные окна** фиксированной длины. Для каждого окна вычисляются агрегированные метрики: число пакетов, пакетов/сек, уникальные IP/порты, распределение по протоколам, статистика по длинам пакетов.
4. На этих метриках обучается **Isolation Forest**. Модель и нормализатор (StandardScaler) сохраняются в файл.

### Режим детекции

1. Загружается сохранённая модель и (опционально) порог по `anomaly_score`.
2. Непрерывный захват пакетов. Каждый пакет:
   - добавляется в **TrafficLogger** — буфер последних N минут трафика;
   - передаётся в **TimeWindowAggregator**.
3. Для каждого завершённого окна модель выдаёт предсказание. При аномалии:
   - в терминал и лог-файл выводятся подробности срабатывания;
   - в SQLite БД сохраняются метаданные (без raw-трафика);
   - формируется ZIP-архив с JSONL-логом трафика и отправляется POST-запросом на веб-сервер (опционально).

### Требования

```bash
pip install pywin32
```

## Конфигурация

Все параметры хранятся в **`config.py`**. Файл делится на четыре блока. Значения из конфига используются как умолчания для CLI и как единственный источник настроек для режима службы.

### Блок `training`

| Параметр | Описание | По умолчанию |
|----------|----------|--------------|
| `interface` | Сетевой интерфейс | `"eth0"` |
| `duration_minutes` | Длительность захвата (мин) | `5` |
| `window_size_seconds` | Размер временного окна (с) | `5.0` |
| `model_path` | Путь к файлу модели | `"anomaly_model.pkl"` |

### Блок `detection`

| Параметр | Описание | По умолчанию |
|----------|----------|--------------|
| `interface` | Сетевой интерфейс | `"eth0"` |
| `window_size_seconds` | Размер окна (с) | `5.0` |
| `model_path` | Путь к модели | `"anomaly_model.pkl"` |
| `score_threshold` | Порог по anomaly_score (`None` = бинарное предсказание модели) | `None` |
| `traffic_log_minutes` | Глубина буфера трафика для ZIP при аномалии (мин) | `5` |
| `alert_server_url` | URL для отправки архива | `"http://127.0.0.1:5000/anomaly"` |
| `send_zip_on_anomaly` | Отправлять ZIP на веб-сервер при аномалии | `True` |
| `log_anomalies_to_sqlite` | Сохранять метаданные аномалий в SQLite | `True` |
| `anomalies_sqlite_path` | Путь к файлу SQLite | `"anomalies.db"` |
| `log_file_path` | Путь к лог-файлу | `"anomaly_detector.log"` |
| `log_stats_interval` | Интервал вывода статистики трафика (с) | `10` |

### Блок `model`

| Параметр | Описание | По умолчанию |
|----------|----------|--------------|
| `contamination` | Ожидаемая доля аномалий в обучающей выборке | `0.01` |

### Блок `service`

Используется только при запуске через `daemon.py`. Аргументы командной строки в этом режиме не применяются — все настройки берутся исключительно из этого блока.

| Параметр | Описание | По умолчанию |
|----------|----------|--------------|
| `interface` | Сетевой интерфейс | `"eth0"` |
| `training_duration_minutes` | Суммарная длительность обучения (мин), накапливается между перезагрузками | `30` |
| `window_size_seconds` | Размер окна (с) | `5.0` |
| `model_path` | Путь к модели | `"anomaly_model.pkl"` |
| `state_file` | Файл состояния обучения (сохраняется между перезагрузками) | `"service_training_state.json"` |
| `log_file_path` | Путь к лог-файлу | `"anomaly_detector.log"` |
| `pid_file` | PID-файл (только Linux) | `"/var/run/anomaly_detector.pid"` |

### Имя интерфейса на Windows

На Windows имя интерфейса для Scapy может отличаться от того, что показывает `ipconfig`. Чтобы найти точное имя, выполните в `cmd`:

```cmd
python -c "from scapy.all import ifaces; [print(i.name, i.ip) for i in ifaces.values()]"
```

Найдите строку с нужным IPv4-адресом. Имя интерфейса будет в первой колонке, например `Ethernet`. Вставьте его в `config.py`:

```python
training = TrainingConfig(interface="Ethernet")
detection = DetectionConfig(interface="Ethernet")
service   = ServiceConfig(interface="Ethernet")
```

## Режимы запуска

Все команды выполняются из каталога `src/`.

### 1. Обучение (`train`)

```bash
# Параметры из config.py
sudo python main.py --mode train

# Явное указание интерфейса, длительности и размера окна
sudo python main.py --mode train --interface eth0 --duration 10 --window-size 5

# Сохранение модели в отдельный файл
sudo python main.py --mode train --model my_model.pkl --duration 5
```

Обучение следует запускать в период нормального трафика без явных аномалий.

### 2. Детекция (`detect`)

```bash
# Параметры из config.py
sudo python main.py --mode detect

# С явными параметрами (размер окна должен совпадать с тем, на котором обучали)
sudo python main.py --mode detect --model my_model.pkl --interface eth0 --window-size 5

# С ручным порогом чувствительности
sudo python main.py --mode detect --score-threshold -0.4
```

Остановка: **Ctrl+C**. В конце выводится итоговая статистика.

### 3. Служба / демон

Режим, при котором программа работает в фоне без терминала. Все параметры — из блока `service` в `config.py`. Состояние обучения сохраняется в `state_file` после каждого завершённого временного окна, поэтому перезагрузка машины не приводит к потере прогресса.

**Логика запуска:**

| Условие | Действие |
|---------|---------|
| Существует `state_file` | Продолжить прерванное обучение |
| Существует `model_path`, нет `state_file` | Пропустить обучение, перейти к детекции |
| Ничего нет | Начать обучение с нуля |

#### Linux

```bash
# Запустить демон в фоне (double-fork daemonization)
sudo python daemon.py start

# Остановить
sudo python daemon.py stop

# Проверить статус
sudo python daemon.py status

# Сгенерировать systemd unit-файл
sudo python daemon.py generate-systemd
```

**Интеграция с systemd:**

```bash
sudo python daemon.py generate-systemd | sudo tee /etc/systemd/system/anomaly_detector.service
sudo systemctl daemon-reload
sudo systemctl enable --now anomaly_detector

# Просмотр логов
journalctl -u anomaly_detector -f
# или напрямую из лог-файла:
tail -f anomaly_detector.log
```

#### Windows

Выполнять в командной строке с правами администратора:

```bat
python daemon.py install   # зарегистрировать службу
python daemon.py start     # запустить
python daemon.py stop      # остановить
python daemon.py remove    # удалить

REM Запустить в терминале (для отладки, без регистрации)
python daemon.py debug
```

После установки служба также доступна в **Диспетчере задач → Службы** под именем `AnomalyDetector`.

## Логирование

В режимах `detect` и служба лог пишется одновременно **в терминал и в файл** (по умолчанию `anomaly_detector.log`). Путь задаётся через `detection.log_file_path` или `service.log_file_path` в `config.py`.

### Периодическая статистика трафика

Каждые `log_stats_interval` секунд (по умолчанию 10) в лог выводится строка:

```
2026-05-03 12:34:10 [INFO] Статистика трафика: за 10 с перехвачено 847 пакетов (84.7 пак/с), всего 1694
```

### Аномалии в логе

При каждом срабатывании в лог добавляется строка уровня `WARNING`:

```
2026-05-03 12:34:15 [WARNING] АНОМАЛИЯ обнаружена: окно 12:34:10 – 12:34:15 | score=-0.3421 | пакетов=423 | pps=84.6 | src_ip=12 | dst_ip=3 | TCP=400 UDP=23 ICMP=0
```

В терминале дополнительно выводится развёрнутый блок с полными деталями по окну.

## База данных аномалий

При включённом `detection.log_anomalies_to_sqlite` метаданные каждой аномалии сохраняются в SQLite (по умолчанию `anomalies.db`). Raw-трафик и payload в БД не записываются.

### Таблица `anomaly_events`

| Колонка | Тип | Описание |
|---------|-----|----------|
| `id` | INTEGER PK | Автоинкремент |
| `created_at` | INTEGER | Unix timestamp записи |
| `interface` | TEXT | Сетевой интерфейс |
| `model_path` | TEXT | Путь к модели |
| `window_start` | REAL | Начало временного окна |
| `window_end` | REAL | Конец временного окна |
| `duration` | REAL | Длительность окна (с) |
| `anomaly_score` | REAL | Оценка аномальности |
| `score_threshold` | REAL | Порог срабатывания |
| `packet_count` | INTEGER | Число пакетов в окне |
| `packets_per_second` | REAL | Пакетов в секунду |
| `unique_src_ip` | INTEGER | Уникальных IP-источников |
| `unique_dst_ip` | INTEGER | Уникальных IP-назначений |
| `unique_src_port` | INTEGER | Уникальных портов-источников |
| `unique_dst_port` | INTEGER | Уникальных портов-назначений |
| `avg_length` | REAL | Средняя длина пакета (байт) |
| `proto_tcp` | INTEGER | Число TCP-пакетов |
| `proto_udp` | INTEGER | Число UDP-пакетов |
| `proto_icmp` | INTEGER | Число ICMP-пакетов |

Индексы: `created_at`, `window_end`.

Пример запроса последних 10 срабатываний:

```bash
sqlite3 anomalies.db "SELECT datetime(created_at, 'unixepoch', 'localtime'), anomaly_score, packet_count, packets_per_second FROM anomaly_events ORDER BY id DESC LIMIT 10;"
```

## Демонстрационный веб-сервер

`alert_server.py` — простой Flask-сервер, принимающий архивы трафика при аномалиях.

```bash
python alert_server.py
```

Слушает на `0.0.0.0:5000`. При получении POST-запроса на `/anomaly` сохраняет ZIP в каталог `uploads/` и выводит сообщение в консоль.

Поля запроса:
- `message` — текстовое описание аномалии;
- `file` — ZIP-архив с JSONL-логом трафика.

В `config.py` должны быть настроены:
```python
detection.alert_server_url = "http://127.0.0.1:5000/anomaly"
detection.send_zip_on_anomaly = True
```

## Признаки и агрегация

### Признаки из каждого пакета

| Признак | Описание |
|---------|----------|
| `timestamp` | Время захвата |
| `src_mac`, `dst_mac` | MAC-адреса |
| `vlan`, `eth_type` | VLAN, тип Ethernet |
| `src_ip`, `dst_ip` | IP-адреса (IPv4/IPv6/ARP) |
| `proto`, `ttl` | Протокол, TTL |
| `src_port`, `dst_port` | Порты (TCP/UDP) |
| `tcp_flags` | Флаги TCP |
| `icmp_type`, `icmp_code` | ICMP тип и код |
| `length` | Длина пакета (байт) |

### Агрегированные метрики окна

| Метрика | Описание |
|---------|----------|
| `packet_count` | Число пакетов |
| `packets_per_second` | Интенсивность |
| `unique_src_ip`, `unique_dst_ip` | Уникальные IP |
| `unique_src_port`, `unique_dst_port` | Уникальные порты |
| `proto_tcp`, `proto_udp`, `proto_icmp` | Счётчики по протоколам |
| `avg_length`, `min_length`, `max_length` | Статистика длин |
| `avg_ttl` | Средний TTL |
| `unique_tcp_flags` | Число уникальных комбинаций TCP-флагов |
| `icmp_count` | Число ICMP-пакетов |

Размер окна задаётся в `config.py` и **должен совпадать** при обучении и детекции.

## Настройка чувствительности

Для Isolation Forest `anomaly_score` находится в диапазоне примерно от -1 до 0. Нормальный трафик даёт score близкий к 0, аномальный — ниже.

| Настройка | Описание |
|-----------|----------|
| `score_threshold = None` | Использовать бинарное предсказание самой модели (на основе `contamination`) |
| `score_threshold = -0.3` | Срабатывать при score < -0.3 (умеренная чувствительность) |
| `score_threshold = -0.5` | Срабатывать при score < -0.5 (высокая чувствительность) |

Рекомендуется запустить детекцию на нормальном трафике, посмотреть значения score в логе и подобрать порог.

## Устранение неполадок

| Проблема | Решение |
|----------|---------|
| Интерфейс недоступен | `ip link show` или `ipconfig /all` — указать правильный интерфейс в `config.py` |
| Permission denied при захвате | Запускать с `sudo` (Linux) или от администратора (Windows) |
| Файл модели не найден | Сначала выполнить обучение: `sudo python main.py --mode train` |
| Мало данных для обучения | Увеличить `duration_minutes` или проверить наличие трафика на интерфейсе |
| Архив не отправляется на сервер | Проверить, что запущен `alert_server.py`, и что в конфиге верный URL; при ошибке архив остаётся локально |
| Демон не запускается на Linux | Проверить права на `pid_file` (`/var/run/`), запускать через `sudo` |
| Windows-служба не устанавливается | Запустить командную строку от администратора; убедиться, что установлен `pywin32` |
| После перезагрузки обучение начинается заново | Проверить, что `service.state_file` и `service.model_path` в `config.py` указывают на постоянное (не временное) место на диске |
